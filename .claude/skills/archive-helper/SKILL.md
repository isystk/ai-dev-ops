# Archive Helper Skill

## Goal

ai-dev-ops リポジトリにおいて、アーカイブが必要なファイルを自律的に検出し、
ユーザーの確認を得たうえで `archive/` フォルダへ移動する。
移動と同時に INDEX.md からも該当エントリを削除し、CLAUDE.md のルール8に準拠した運用を維持する。

## 絶対ルール

- **一問一答の厳守**: ユーザーに一度に複数の質問をしない。
- **必ず `git mv` を使用**: 履歴を保持するため `mv` ではなく `git mv` を使う。
- **destructive操作は事前確認**: 移動前に必ず候補一覧をユーザーに提示し、承認を得る。
- **INDEX.md と同期**: ファイル移動と同じターンで INDEX.md の「廃止・置換済み」欄から該当行を削除する。
- **アーカイブ後の空フォルダ**: 元フォルダが空になった場合は `.gitkeep` を配置する。
- **対象範囲を明示**: 全プロジェクト走査か、特定プロジェクトかを最初に確認する。

---

## 起動時の動作

スキル起動時、以下を宣言してから情報収集を開始する：

```
Archive Helper スキルを開始します。
CLAUDE.md ルール8（イベント駆動アーカイブ）に従い、アーカイブ候補を検出します。
```

---

## Phase 1: 対象範囲の確認（ユーザーへの質問）

**Q1**: アーカイブ候補を検出する対象を選んでください。
- a) 全プロジェクト走査
- b) 特定プロジェクト（プロジェクト名を指定）
- c) 特定パス（フォルダパスを指定）

（省略時は a の全プロジェクト走査）

---

## Phase 2: 候補の自律検出（ユーザーへの質問なし）

Q1の回答後、ユーザーへの質問を止め、以下のルールでアーカイブ候補を自律的に検出する。
各検出ステップ前に「〇〇を走査中...」と進捗を1行で報告する。

### 検出ルールA: 改訂版あり原本

`成果物/` 配下で、ファイル名に `_改訂版` を含むファイルが存在するとき、
同名から `_改訂版` を除いたファイル（または同テーマの旧版日付ファイル）を候補とする。

例:
```
2026-05-22_Note連載小説_第1話_改訂版.md  ← 現行
2026-05-18_Note連載小説_第1話.md          ← 候補（同テーマ・旧日付）
2026-05-22_Note連載小説_第1話.md          ← 候補（同日・改訂版でない原本）
```

検出コマンド例:
```bash
find projects -type f -name "*_改訂版.md" | while read rev; do
  base=$(basename "$rev" | sed 's/_改訂版\.md$/.md/')
  dir=$(dirname "$rev")
  find "$dir" -type f -name "*${base#*_}" -not -name "*_改訂版*"
done
```

### 検出ルールB: INDEX.md「廃止・置換済み」欄に記載されたファイル

各担当フォルダ・共有情報フォルダの `INDEX.md` を読み込み、
「## 廃止・置換済み」セクションに列挙されているファイルパスを候補とする。

CLAUDE.md ルール8 では「2週間以上掲載」が基準だが、本スキルでは**全件を候補提示し、
個別にユーザー判断**とする（記載日が分からないため）。

### 検出ルールC: `共有情報/方針/` に複数フェーズが残存

`共有情報/方針/` 内に2ファイル以上ある場合、最新日付以外を候補とする。
（新フェーズ追加時に旧フェーズが移動されていないケース）

### 検出ルールD: 一次情報の対応完了候補

`共有情報/一次情報/` 配下のファイル名から、依頼の宛先担当を抽出し、
当該宛先の `成果物/` または `確定情報/` に対応する成果物があれば候補として提示する。
判定は AI で実施し、ユーザーに「対応完了か」を確認する。

### 検出ルールE: Active欄の完了記録

各担当・共有情報の `INDEX.md`「いま有効な成果物（Active）」欄を走査し、
以下の両方を満たすエントリを候補とする（CLAUDE.md ルール8「各担当の成果物（完了記録）」に対応）：

1. サマリ冒頭・文中に完了系タグがある（例:「対応完了」「本番反映済み」「調査完了・対応不要」「実装完了」等）
2. 「次アクション」記述が無い、または「ユーザー対応待ち」のみで技術側のフォローアップが無い

判定は AI で実施（タグ・次アクション記述の有無を機械的にチェック）し、
一覧提示のうえ必ずユーザーに個別確認する。誤検出防止のため、進行中フェーズに紐づくもの
（例: `## 現行フェーズ` からリンクされている成果物）は自動除外し候補に含めない。

併せて、Active欄のエントリが**一行サマリを超えて全文詳細化している場合**は、
アーカイブ候補提示と同じフェーズで「一行サマリへの圧縮」も提案する（CLAUDE.md ルール9準拠）。

---

## Phase 3: 候補一覧の提示

検出した候補を以下のテーブル形式で提示する：

```markdown
## アーカイブ候補

| # | プロジェクト | 検出ルール | 元ファイル | 移動先 | 理由 |
|---|---|---|---|---|---|
| 1 | sample | A | cqo/成果物/xxx.md | cqo/archive/ | _改訂版あり |
| 2 | sample | B | cto/成果物/yyy.md | cto/archive/ | INDEX.md廃止欄に記載 |
| 3 | sample | C | 共有情報/方針/旧フェーズ.md | 共有情報/archive/方針/ | 新フェーズ存在 |
```

**続けて以下を質問する：**

**Q2**: どの候補をアーカイブしますか？
- a) すべて実行
- b) 番号で個別指定（例: 1,3,5）
- c) キャンセル

---

## Phase 3.5: 確定情報反映チェック（ユーザーへの質問なし・Q2で選択された候補のみ）

**archiveは削除ではなく移動だが、`共有情報/確定情報/`へ転記されないまま埋もれると
実質的に参照されなくなる。移動前に必ずこのチェックを行う。**

Q2で選択された候補それぞれについて、移動を実行する**前**に以下を行う：

1. ファイル内容を確認し、恒久的に効く仕様・設定変更（DB設定値、決済/API仕様、環境変数、
   本番運用ルール、機能仕様等）を含むか判定する
   - 含まない（単発調査・トラブルシューティングのみ・実装完了報告だが仕様変更を伴わない）
     → そのままarchiveへ進む
   - 含む → 次のステップへ
2. `共有情報/確定情報/` 配下の該当機能ファイルを確認する
   - 既に反映済み → そのままarchiveへ進む
   - 未反映/古い → 該当ファイルの「現在仕様」を実装内容に合わせて更新し、「変更履歴」に
     日付・変更内容・移動後のarchiveパスへのリンクを追記してからarchiveへ進む
   - 該当ファイルが存在しない → 無理に新規作成せず、候補一覧の「要確認」として報告に残す
     （ユーザーに新規作成要否を確認する）
3. 判定に迷う場合はarchiveを止めず、恒久仕様の疑いがある旨を注記してPhase 5の報告に含める
   （移動自体は止めない。確定情報反映の要否判断は事後でも可能なため）

---

## Phase 4: 実行（ユーザーへの質問なし）

Q2の回答に従い、以下を実行する。

### Step A: ファイル移動

選択された候補それぞれについて：

```bash
git mv "{元パス}" "{移動先ディレクトリ}/"
```

### Step B: INDEX.md の更新

移動したファイルが各担当/共有情報の `INDEX.md` に記載されている場合、
「廃止・置換済み」セクションから該当行を削除する。

セクションが空になった場合は「（なし）」と記載する。

### Step C: 空フォルダへの .gitkeep 配置

移動元フォルダが空になった場合、`.gitkeep` を配置する。

```bash
if [ -z "$(ls -A {元フォルダ})" ]; then
  touch {元フォルダ}/.gitkeep
fi
```

---

## Phase 5: 完了報告

実行後、以下を報告する：

```
アーカイブ完了。

移動件数: {N}件
- {元パス} → {移動先}
- ...

確定情報への反映（Phase 3.5）: {N}件更新
- {確定情報ファイル} ← {元archiveファイル}
- ...
要確認（確定情報ファイル未整備・新規作成要否判断待ち）: {N}件

更新したINDEX.md:
- {INDEXパス}: 廃止・置換済み欄から{N}件削除
- ...

git status: 変更 {N}件（コミット推奨）
```

---

## 注意事項

- `共有情報/確定情報/` 配下の **機能別仕様ファイル**（例: `料金プラン.md`）は **原則アーカイブしない**。
  仕様は既存ファイル更新で運用するため。機能自体を廃止した場合のみアーカイブする（要ユーザー明示確認）。
- `共有情報/方針/` のアーカイブ先は `共有情報/archive/方針/`、
  `確定情報/` のアーカイブ先は `共有情報/archive/確定情報/`、
  `一次情報/` のアーカイブ先は `共有情報/archive/一次情報/`。
- 各担当の `成果物/` のアーカイブ先は `各担当/archive/`。
- 検出ルールA（改訂版あり原本）は誤検出の可能性があるため、ユーザー確認を必ず行う。
- 検出ルールD（一次情報の対応完了）は AI 判定なので、必ずユーザー確認を行う。
- 検出ルールE（Active欄の完了記録）も AI 判定（タグ・次アクション文言の機械抽出）なので、必ずユーザー確認を行う。進行中フェーズにリンクされる成果物は自動除外するが、判断に迷うものは候補から外さず理由付きで提示しユーザー判断に委ねる。
- 移動後の検証として `git status` を実行し、想定どおりの変更になっているか確認する。
