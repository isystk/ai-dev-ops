# ai-dev-ops

AIエージェントを活用した AIチームエージェント運用リポジトリのテンプレートです。
秘書・CTO（開発担当）・CQO（品質担当）・CSO（セキュリティ担当）・CIO（インフラ担当）の
各担当を AI エージェントが担い、ITエンジニアの開発業務を支援します。

isystk-biz-ops（個人事業向け全担当版）を、ITエンジニア向けに担当構成を絞って簡易化したものです。

## 担当一覧

| 担当 | 役割 |
|---|---|
| 秘書 | 仕事の整理・AIへの指示・進捗管理（フォルダ無し・全社ハブ） |
| CTO（開発担当） | 設計・実装・技術判断 |
| CQO（品質担当） | 品質保証・レビュー・テスト |
| CSO（セキュリティ担当） | セキュリティ対策・脆弱性診断・監査 |
| CIO（インフラ担当） | インフラ構築・運用・CI/CD |

|---|---|

## フォルダ構成

```
ai-dev-ops/
├── README.md                       # このファイル
├── CLAUDE.md                       # Claude Code 全担当共通ルール
├── .claude/skills/                 # プロジェクト専用スキル
│   └── archive-helper/             # アーカイブ運用支援スキル
└── projects/                       # プロジェクト別フォルダ
    └── {プロジェクト名}/
        ├── cto/
        │   ├── INDEX.md            # 現在地マップ（必須・最初に読む）
        │   ├── 成果物/             # Activeな成果物
        │   └── archive/            # 旧版・廃止済み
        ├── cqo/{INDEX.md, 成果物/, archive/}
        ├── cso/{INDEX.md, 成果物/, archive/}
        ├── cio/{INDEX.md, 成果物/, archive/}
        └── 共有情報/
            ├── INDEX.md            # 現在地マップ（必須・最初に読む）
            ├── 確定情報/           # 機能別の現在仕様（SSoT・永続）
            ├── 方針/               # フェーズ単位の時系列意思決定
            ├── 一次情報/           # 担当間の依頼書
            └── archive/{確定情報/, 方針/, 一次情報/}
```

## ドキュメント運用ルール

詳細は [`CLAUDE.md`](./CLAUDE.md) を参照。要点は以下のとおりです。

### INDEX.md（現在地マップ）

各担当フォルダ・`共有情報/` フォルダ直下に必ず `INDEX.md` を配置します。
**AIや人間がフォルダを参照する際は、必ず最初に `INDEX.md` を読みます。**

- いま有効な成果物（Active）の一覧
- 進行中タスク
- 廃止・置換済み（archive移動候補）

成果物を新規作成・改訂・廃止したら、**同じコミット内** で `INDEX.md` を更新します。

### 共有情報フォルダの3つのサブフォルダ（役割分担）

| フォルダ | 役割 | 命名 | 更新方法 |
|---|---|---|---|
| `確定情報/` | 機能別の**現在仕様**（SSoT・永続） | `{機能名}.md`（例: `認証方式.md`） | 既存ファイルを更新 |
| `方針/` | フェーズ単位の**時系列意思決定** | `YYYY-MM-DD_フェーズN.md` | 新フェーズで新ファイル追加 |
| `一次情報/` | 担当間の**依頼書** | `YYYY-MM-DD_{依頼元}より_..._{依頼先}{確認/対応}依頼.md` | 対応完了後 archive へ |

**「確定情報/ を見れば現在の正確な仕様が分かる」状態を維持します。**
仕様変更は **新ファイル追加ではなく既存ファイル更新** で行います。

### アーカイブ運用（イベント駆動）

時間経過ではなく **明確なイベント** でアーカイブを実行します。

| トリガー | アクション |
|---|---|
| `_改訂版` を作成した瞬間 | 原本を即 `archive/` へ |
| 新フェーズが `方針/` に追加された瞬間 | 旧フェーズを `archive/方針/` へ |
| `一次情報/` の依頼が対応完了した瞬間 | `archive/一次情報/` へ |
| `INDEX.md` の「廃止・置換済み」欄に2週間以上掲載 | `archive/` へ |

- 移動は **必ず `git mv`** を使用（履歴保持）
- `archive/` 内のファイルは削除しない（検索・参照は引き続き可能）
- アーカイブと同時に `INDEX.md` から該当エントリを削除する

### 成果物のフロントマター（新規作成分から適用）

今後新規作成する成果物には、以下のフロントマターを付与します（既存ファイルへの遡及適用は不要）。

```yaml
---
status: active        # active | superseded | draft | archive-pending
created: YYYY-MM-DD
supersedes:           # 置換した旧ファイル名（あれば）
related_phase:        # 関連フェーズ
owner: cto            # cto | cqo | cso | cio
---
```

AI は `status: superseded` および `archive-pending` のファイルは原則として読み込みません。

### 基本ルール

- 成果物は `{担当}/成果物/` に日付付きファイル名で保存
- 外部素材・調査の生データは `共有情報/一次情報/` に統合
- 他の担当に関係する情報は必ず共有
- 事実と意見を分けて記述
- 出力はすべて日本語

## 利用可能なスキル

`.claude/skills/` 配下にプロジェクト専用スキルを配置しています。

| スキル名 | 用途 |
|---|---|
| `archive-helper` | アーカイブ候補を4ルール（改訂版検出・INDEX記載・旧フェーズ・一次情報完了）で自動検出し、対話形式で `git mv` 実行する |

スキルは Claude Code 起動後、自然言語または `/{スキル名}` で起動できます。

```
/archive-helper
```

## 使い方

```bash
# リポジトリルートで Claude Code を起動
claude
```

### 新しいプロジェクトを追加する場合

1. `projects/sample/` をコピーして `projects/{プロジェクト名}/` を作成
2. 各担当・共有情報の `INDEX.md` の内容を新規プロジェクト用に書き換える
3. ルート [`CLAUDE.md`](./CLAUDE.md) の「関連プロジェクト」テーブル、および本 README の「関連プロジェクト」一覧に追記する

### よくある操作

| やりたいこと | 操作 |
|---|---|
| 現在の状態を把握したい | 該当プロジェクトの各 `INDEX.md` を参照 |
| 機能の現在仕様を知りたい | `共有情報/確定情報/{機能名}.md` |
| 全体方針・フェーズを知りたい | `共有情報/方針/` の最新ファイル |
| アーカイブ整理したい | `/archive-helper` スキル起動 |
